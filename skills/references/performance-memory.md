# 演算法、效能與記憶體

> 何時讀：處理外部大小的輸入、熱點路徑、做優化、訂效能預算、審查效能宣稱時。原則：**先量測、不提前優化**。

## 演算法與效能
1. **先量測**：用 profiler／benchmark（criterion、`cargo flamegraph`、Chrome DevTools、Vitest bench、`Measure-Command`）找真瓶頸，記基準數字。沒數據不優化。
2. **推導複雜度**：寫出現況與新解法的時間／空間 Big-O 與一兩行推導（例：「外層 n × 內層線性搜尋 n = O(n²)；改 HashMap O(1) 均攤 → O(n)」），說明 n 的實際規模與常數因子。
3. **選對工具**：雜湊、排序＋二分、雙指標、滑動視窗、前綴和、DP、貪婪（要能證明貪婪選擇性質）、BFS/DFS/Dijkstra、堆（Top-K）、Trie、並查集、分治、memoization、串流與增量計算、位元運算。平行化只在量測證明 CPU 是瓶頸且資料可切分時。
4. **證明正確**：迴圈不變量、終止條件、邊界（空、單一元素、重複值、溢位、極大 n），用單元或性質測試涵蓋。
5. **簡單優先**：n 小或不在熱點就選最易讀的；換複雜演算法要在註解寫理由與複雜度。
6. **記錄前後數字**：中位數、樣本數、機器環境。

## 效能規則
- **效能預算**：預製期為關鍵操作訂可量測目標（例：UI 互動 < 100 ms、啟動 < 2 s、10 萬筆 < 1 s、記憶體上限），寫進工單驗收條件。
- **複雜度上限**：外部決定大小的輸入在熱點上不得 O(n²) 以上，除非有硬上限並說明；遞迴要確認深度上限。
- **效能回歸測試**：有預算的操作加 benchmark，以代表性資料量測，超出預算或退步超過約定比例（例 20%）就失敗。

## 記憶體與資源
| 原則 | 寫法 |
|---|---|
| 所有權與生命週期明確 | 優先借用、區域變數；跨執行緒共享用不可變資料或 `Arc`，需寫入才上鎖；避免循環參照（必要時 `Weak`）；TS 移除監聽、timer、subscription |
| 延遲配置、積極釋放 | 需要時才建大物件；資源用 RAII／`Drop`／`try/finally`／`using` 收尾；不在全域或長壽快取留不需要的資料 |
| 重用與池化 | 連線、執行緒、HTTP client 用池或共用實例——**只在量測證明有成本時** |
| 防禦性容量上限 | 外部決定大小的配置（分頁、上傳、檔案、佇列、快取、訊息）都設硬上限；channel／佇列用有界版本；大資料用串流或游標 |
| 空間局部性 | 熱路徑用連續記憶體（`Vec`、陣列、`TypedArray`）——**只在熱路徑且量測過** |

**記憶體測試**：超過上限的輸入會被截斷或拒絕；大資料情境證明是串流（記憶體不隨資料量線性成長）；長時間執行的流程做一次記憶體穩定性檢查。
