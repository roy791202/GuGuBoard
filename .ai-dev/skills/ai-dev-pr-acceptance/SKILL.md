# PR 驗收期（獨立驗證代理）

## 身分檢查（先做）
- 你必須是**另外啟動**的代理，不是寫這張工單的代理，也不延續它的對話。是同一個 → 停止，回報驗收無效。
- 你不改產品程式碼與測試；發現問題只記錄並退回。
- 不採信開發代理的「已測過」，一切重新實測。

細則在 `.ai-dev/references/verification.md`（怎麼測、提問協定、審查清單），其中每列再指向對應的細則檔，用到才讀。

## A. 實測（中低階模型）
1. 依測試清單重跑自動化測試（含分層依賴檢查、覆蓋率、安全與錯誤情境、效能回歸）；能在多個目標平台跑就各跑一次。
2. 依介面實測步驟**實際操作產品介面**，每步截圖、關鍵流程錄影，存到約定的證據資料夾。
3. 主動找破口、確認測試可信（變異測試）。
4. 逐項記 PASS／FAIL／NOT RUN（不得偽造 PASS）。有 FAIL 就退回，附步驟、輸入、預期、實際與截圖。

## B. 審查（高階模型）
1. 依 `verification.md` 的審查清單逐面向檢查：範圍、架構、寫法、註解、上線就緒、效能與記憶體、BDD＋TDD、hook 與 CI、看板、版本。
2. 看不懂的寫法用提問協定問開發代理，提問期間卡片黃燈。
3. 明顯違反就退回並列出要修改的項目；小問題列建議不擋 PR。

## 結果
- **PASS**：在工單備註與 PR 留言寫驗收紀錄（開發者與驗證者身分、指令與輸出、證據連結、涵蓋的情境 ID），並告訴人：可以用情境端點把這些情境標 Green、合併 PR、標 Done（D1、D4）。你自己不設 Done／藍燈。
- **退回**：卡片回 In Progress、黃燈（第二次以上紅燈），`lightReason` 寫原因，附證據。

## 完成關卡
有產出、獨立實測通過、獨立審查通過，三項都成立才建議人標完成。
